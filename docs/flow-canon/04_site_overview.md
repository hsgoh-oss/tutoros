> 금전 처리와 수업 상태를 분리하지 않는다. 환불·회차 사건 뒤 잔액과 등록 상태를 함께 재판정한다.

### 환불
- [ ] 요청·권한
- [ ] 원 계약·결제
- [ ] 기준시점·정책 계산
- [ ] 운영자 승인
- [ ] 외부 실행
- [ ] 청구·수납·잔액·등록·증빙·포털 정합성

### 수업 생애주기
- [ ] 수업·취소·노쇼·보강
- [ ] 잔액 조정
- [ ] 묶음 마감
- [ ] 갱신·정지·종료
- [ ] 미래 회차·정산·접근 처리
- [ ] 필요 시 재등록 네 조건 재확인

### 예외 대응
- [ ] **환불 결과 불명** — 확정을 보류하고 실제 성공액을 조회해 다시 계산한다.
- [ ] **종료** — 미래 회차 중단 → 최종 정산·기록 → 접근 회수 → 보존기한.
- [ ] **재등록** — 기존 학습이력을 이어도 관계·계약·결제·일정은 다시 확인한다.

## 13. 후기·성적사례·입시정보·운영분석 (S-01–S-07)

> 공개 콘텐츠는 동의·사실·증빙·출처를 운영자가 확인한 승인본만 게시하고, 철회·만료를 지속 감시한다.

### 후기·성적사례
- [ ] 작성 대상·역할·공개범위 확인
- [ ] 초대·동의
- [ ] 제출
- [ ] 필요한 증빙 격리·안전 검사
- [ ] 사실·표현 검토
- [ ] 게시·철회

### 입시정보·분석
입시정보:
- [ ] 공식 출처·범위
- [ ] 수집·정규화
- [ ] 기존 일정 비교
- [ ] 운영자 검토·승인
- [ ] 게시·캘린더 내보내기

분석:
- [ ] 승인 사실 집계
- [ ] 주간 보고

### 예외 대응
- [ ] **증빙 위험** — 비공개 격리 후 안전 변환·거절·재제출로 닫는다.
- [ ] **출처 변경** — 최신성·공식성을 재확인해 수정·철회·만료한다.
- [ ] **분석** — 누락과 지표 정의를 확인하고 운영자 승인본만 확정한다.

## 14. 오늘 업무·외부 장애·백업·릴리스·사고 (W-01–W-08)

> 자동으로 끝나지 않는 예외는 운영자 오늘 업무로 만들고, 복구 뒤 재조회·대사·정합성 확인까지 수행한다.

- [ ] 처리·승인
- [ ] 결과 대사

### 예외 대응

- [ ] **백업·복원** — 무결성 → 격리 복원 → 과거 파기 재적용 → 관계·금전·권한 정합성.

## 15. 개인정보 권리·보존·자동파기·외부 AI (D-01–D-09)

> 접근 회수, 법정 보존, 실제 삭제는 서로 다른 흐름이다. 자동파기는 운영자 승인과 잔존 확인 뒤에만 완료된다.

- [ ] **외부 AI** — 목적·보낼 정보·제공자를 안내하고 동의·철회·수동 대체 경로를 유지한다.
