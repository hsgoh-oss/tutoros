  - [ ] 필수 전달 근거 유지: 선택 채널 해제가 법정·보안·계정 복구 등 별도 필수 전달의 근거를 자동 제거하지 않는다.

  - [ ] 근거 부족: 계산 중단 → 수업·수납 사실 보완.
  - [ ] 분쟁·법정 검토 필요: 실행 보류 → legal hold 또는 검토 흐름.
  - [ ] 완료: 실행 가능한 단일 계산본.
- **현행 갭:** ❌ 없음 — 관련 코드 없음(환불 기준시점·정책 적용·계산 근거 고정 로직 부재)

### F-03 환불 승인·실행
- [ ] **구현 완료** — 승인된 계산본이 원 결제수단 환불·취소로 실행되고 중복 실행이 최초 결과로 수렴한다.
- **주 전환:** 운영자 계산 검토 → 승인 또는 거절
- **예외·복구·종료:**
  - [ ] 부분취소 API 미지원: 같은 승인본으로 수기 환불 경로.
  - [ ] 동일 승인본의 중복 실행: 최초 실행 결과로 수렴.

- **현행 갭:** ❌ 없음 — 관련 코드 없음(환불 승인·실행·중복 실행 수렴 로직 부재)

### F-04 환불 후 정합성
- [ ] **구현 완료** — 환불 후 수납·청구·회차·등록·증빙·포털이 같은 최종 상태로 수렴한다.
- **주 전환:** 외부 환불 성공 → 수납·청구 합계 갱신 → 남은 회차·시간 조정 → 등록 유지·정지·종료 판정 → 증빙 영향 처리 → 포털 상태·안내 갱신
- **예외·복구·종료:**
  - [ ] 어느 하나라도 불일치: 환불 완료는 유지하되 정합성 복구 업무 생성.
  - [ ] 종료 조건: 정합성 복구 후 모든 화면과 운영업무가 같은 최종 상태로 수렴해야 종료.
  - 정합성 복구 후 모든 화면과 운영업무가 같은 최종 상태로 수렴해야 종료.
- **현행 갭:** ❌ 없음 — 관련 코드 없음(환불 후 수납·청구·회차·등록 재계산 및 정합성 복구 업무 부재)

## 17. 수업 잔액·갱신·일시정지·종료·재등록 (E-01 ~ E-05)

### E-01 회차·시간 잔액 반영
- [ ] **구현 완료** — 회차 사건이 승인된 차감정책 판정과 조정 이력으로 잔액에 반영되고 관련 화면이 갱신된다.
- **주 전환:** 회차 종료·취소·노쇼·보강·환불 사건 → 승인된 차감정책 판정 → 잔액 조정 이력 → 현재 잔액 재계산 → 관련 포털·운영업무 갱신
- **예외·복구·종료:**
  - [ ] 이중 차감 금지: 같은 회차 이중 차감 금지.
  - [ ] 출결 정정: 반대 조정 → 새 잔액 계산.
  - [ ] 환불 계산 중 잔액 변경: 기존 환불 계산 무효 → 재검토.
- **현행 갭:** 🔶 부분 — `app/admin/(protected)/lessons/actions.ts:54` · `lib/types.ts:150` · `lib/types.ts:158` — 회차 자동 채번·출결(absent)·일정 취소/보강(canceled·makeup) 사건 기록은 있으나, 잔액·차감정책·조정 이력·재계산 개념이 없음.

### E-02 다음 수업 묶음 갱신
- [ ] **구현 완료** — 현재 묶음 마감 검토와 계속 여부 확인으로 계속·보류·종료가 각 흐름으로 수렴한다.
- **주 전환:** 현재 묶음 마감 검토 → 남은 회차·보강·미수·환불·진도 확인 → 계속 여부 확인
- **예외·복구·종료:**
  - [ ] 미확정 시 회차 확정 금지: 결제 또는 일정이 미확정이면 다음 회차를 확정하지 않는다.
  - [ ] 조건 변경: 조건 변경은 새 계약 동의 후 진행.
  - 분기·상태 수렴: 계속 → 조건 동일 또는 변경 계약 동의 → 새 청구 → 결제 확인 → 다음 일정 확정 → 다음 수업 묶음 활성 / 보류 → 후속 상담·미수·일정 업무 / 종료 → 최종 정산·등록 종료

### E-03 일시정지·재개
- [ ] **구현 완료** — 정지 합의·미래 회차 조정·재개 시 재확인·새 회차 생성으로 등록이 정지·재활성된다.
- **주 전환:** 정지 요청 → 사유·기간·예정 회차·청구·잔액 처리 합의 → 미래 회차 중단·조정 → 등록 정지 → 재개 시점 확인 → 계약·정원·결제·일정 재확인 → 새 회차 생성 → 등록 재활성

### E-04 등록 종료

### E-05 재등록
