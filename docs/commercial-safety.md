# 운영 저장 흐름 보강 (2026-09-14)

이 변경은 캘린더 등록·차감, 조회 실패 표시, 운영 인증, 콘텐츠 복원과 개인정보 파기 실행을 보강합니다. 법정 보존기간을 새로 정하거나 외부 처리자의 삭제를 자동으로 보장하는 변경은 아닙니다. 보존기간은 기존 처리방침을 그대로 사용합니다.

## 배포 순서

1. 운영 DB 백업을 확보하고 `00027_calendar_registration.sql` → `00028_atomic_content_restore.sql` → `00029_privacy_erasure.sql` 순서로 적용합니다. 기존 데이터의 삭제·파기는 마이그레이션으로 실행하지 않습니다.
2. `AUTH_DEV_MODE=false`, 무작위 32자 이상의 `AUTH_SECRET`, Supabase와 인증 메일 환경변수를 설정합니다. 운영에서 개발 OTP 표시를 켜거나 약한 키를 쓰면 시작/인증을 거부합니다. 인증 키를 바꾸면 기존 세션은 다시 로그인해야 합니다.
3. 앱을 배포합니다. 새 컬럼과 RPC가 필요하므로 DB 적용이 먼저입니다. Storage에는 `materials`, `homework`, `review-evidence` 비공개 버킷과 `reviews` 공개 버킷이 필요합니다. 기존 셋업 절차는 `docs/supabase-setup.md`를 따릅니다.

이번 검증은 로컬 Supabase와 별도 검증 DB에서 실행했습니다. 운영 DB 적용과 배포는 별도입니다.

## 동작

- 캘린더에서 등록하면 수업 시각에 유효한 활성 묶음과 동의된 계약을 함께 연결합니다. 후보가 여러 개면 자동 연결을 차단합니다. `차감 없는 수업`을 직접 선택할 수도 있습니다. 실제 차감은 출결 확정 시 발생하며, 같은 학생에 대한 동시 등록은 DB에서 직렬화합니다.
- 캘린더·학생·보존기록 조회 실패는 빈 목록으로 표시하지 않습니다. 오류 안내와 재시도 버튼이 나타납니다.
- FAQ, D-day, 후기, 모집 현황, 설정 복원은 DB 트랜잭션에서 검증한 다음 적용합니다. 검증과 적용 사이의 변경을 감지하면 재시도를 요구합니다. 실패하면 변경 전체를 되돌립니다. 복원 직전 상태도 백업하며 최근 12개를 보관합니다.
- 후기는 비공개 초안으로 복원하고 현재 철회 상태를 보존합니다. 파기한 후기는 복원 및 이후 백업 저장에서도 제외합니다.

## 개인정보 파기

보존기록에서 **파기 범위 확인 → 원본·첨부파일 삭제 → 외부 확인 후 파기 완료** 순으로 실행합니다. 실행은 관리자 인증, 확인 입력과 감사 기록을 요구합니다. 기한 전·보존 잠금·진행 중인 관련 업무·등록·거래는 차단합니다. 과거 수기 완료 기록은 실제 삭제가 검증된 기록과 구별해 표시합니다.

| 범주 | 서버에서 삭제하는 범위 | 별도로 보존하는 범위 |
| --- | --- | --- |
| 학생 서비스 | 개인 프로필 익명화, 일정·출결·수업·과제·AI·성적·자료, 알림, 포털 관계·접근 | 계약·신청·동의·결제·후기·감사 증적. 다른 학생과 공유하는 보호자 연락처 |
| 상담 | 미전환 상담·신청폼·시범 결과·대기 | 동의 증명은 별도의 상담 종료 후 1년 기록 생성 |
| 신청·동의 | 대상의 동의 이력, 종료된 학생 등록에 연결된 신청폼 | 계약·거래 증적 |
| 결제 | 해당 결제·결제사 수신 기록, 관련 계약·묶음 증적 | 연결된 계약/거래의 기한이 하나라도 남아 있으면 실행 차단 |
| 후기 | 철회된 후기·초대·첨부파일, 해당 후기의 콘텐츠 백업 | 최소 파기 기록과 복원 방지 ID |

DB 삭제와 파일 목록은 함께 저장됩니다. 파일 실패 후에도 진행 상태가 남으며 **첨부파일 삭제 재시도**로 이어갈 수 있습니다. 잘못된 경로나 다른 테넌트 경로는 삭제하지 않습니다. 경로 오류는 원본 파일의 소유 범위를 점검하고 작업 목록을 수정한 뒤 재시도해야 합니다. 파일 삭제 완료만으로 전체 파기를 완료 처리하지 않습니다.

외부 처리자, 내려받은 사본, DB 스냅샷/PITR, 정적·외부 이미지와 별도 감사 증적은 이 앱이 일괄 삭제하지 않습니다. 운영자가 각 보존 목적·기한을 확인하고 삭제 또는 만료, 복원 방지 조치의 근거를 남겨야 최종 완료됩니다. DB 전체 복원 시에도 최신 파기 원장·복원 방지 ID를 먼저 보존하고 재적용해야 합니다. 코드가 자동 기산하지 않는 사건은 보존기록 화면에 계속 표시합니다.

## 검증

```sh
# 로컬 PostgreSQL의 tutoros_commercial_verify DB를 재생성합니다.
pnpm verify:commercial
pnpm typecheck
pnpm lint
pnpm audit:scope

# 로컬 Supabase + 개발 서버. 실제 서비스 자료가 아닌 격리된 테스트 자료를 만듭니다.
CALENDAR_INTEGRATION=1 pnpm test:e2e --project=admin

# 별도 디렉터리에서 만든 운영 빌드로 시작 거부, 오류 안내·재시도를 확인합니다.
node scripts/verify-production-runtime.mjs /path/to/isolated-build
```

SQL 검증은 각 테스트를 롤백합니다. 브라우저 검증은 테스트 학생·후기·보존기록·파일·임시 버킷을 정리하고 감사 로그만 남깁니다. 운영 모드 검증은 임시 인증 세션을 정리하며, 실제 메일·문자·결제는 전송하지 않습니다.
